# 程序设计说明

我以 **啊Siri / zzh096** 署名，在项目中担任主程序。以下介绍游戏程序系统的职责与设计重点，不将团队所有代码或创作成果归为个人独立完成，也不包含未获确认的源代码。

## 统一交互

输入层集中读取键盘与鼠标，场景交互入口负责选择目标，再区分查看、拾取和道具使用。机关共用输入与交互规则，暂停、阻塞对白和小游戏出现时共同管理输入状态。

设计重点是让玩家的相同操作在不同房间保持一致，并处理图片位置、交互范围、重叠目标和当前选中道具之间的关系。

## 自动存档与状态恢复

存档保存稳定的道具 ID 和状态数据，而非 Unity 场景组件引用。库存、收集记录、机关和剧情阶段一起恢复，避免只恢复角色位置而丢失解谜进度。

进度由会话层集中捕获；加载时校验库存和机关状态，失败路径保留或恢复有效状态。测试使用独立存档入口，避免覆盖玩家实际进度。

## 解谜小游戏

第三章包含动物配对、透卡对齐和雨棚修补。小游戏需要处理拖动位置、旋转、松手判断、错误回退与正确放置后的保留，再把已完成部分交给章节状态系统。

交互、显示和完成状态分别管理，便于调整美术布局，也便于恢复中途退出前的有效进度。

## 剧情与 CG

文本和选项由配置驱动。CG 显示管理图片、人物图层、逐字文本节奏、阅读缓冲、暂停、长按跳过与退出转场，章节推进在演出完成后衔接。

人物图层可以在特定文本节点开始淡出；收尾演出采用独立播放节奏，使普通探索对白和章节 CG 保持各自的交互方式。
